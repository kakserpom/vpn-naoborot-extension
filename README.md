## Новое: выборочное проксирование по списку сайтов

В старой версии PAC-скрипт был жёстким: всё, кроме API, шло через прокси.
Теперь в popup сразу на верхнем уровне выведены два режима:

* **«Только сайты из списка»** — через прокси идут только сайты из списка, остальные напрямую (режим по умолчанию, идёт первым);
* **«Все сайты через VPN»** — через прокси идёт всё, кроме сайтов, помеченных «напрямую».

Для каждого домена выбирается действие: «Через VPN» или «Напрямую».
Домен можно ввести в любом виде (`https://gosuslugi.ru/path`, `*.gosuslugi.ru`, `gosuslugi.ru:443`) —
он приводится к нормальному виду. Правило действует и на поддомены
(`gosuslugi.ru` покрывает `www.gosuslugi.ru`).

Поле ввода подхватывает контекст вкладки, по иконке расширения которой открыт popup
(для этого в манифесте есть `activeTab`): в placeholder ставится домен активной вкладки,
а «Добавить» при пустом поле добавляет именно текущий сайт.

«Добавить» идемпотентно: если домен уже в списке с выбранным действием — ничего
не меняется, а если с другим — пометка просто обновляется; ошибок при этом нет,
кнопка плавно подсвечивается зелёным на секунду, а надпись «Добавить» сменяется
галочкой. Новые домены попадают в начало
списка. Кнопки **«Готовый список»** и **«Очистить список»** позволяют быстро залить
дефолтный набор или удалить всё сразу.

По умолчанию включён режим **«Только сайты из списка»**, а в списке — 57 популярных
российских сервисов (`src/shared/defaults.ts`): Госуслуги, ФНС, ПФР, Минюст, ФССП,
Росреестр, ГИБДД, ЦБ РФ, суды (`sudrf.ru`, `vsrf.ru`, `mos-gorsud.ru`, `kad.arbitr.ru`),
Почта России, СДЭК, Boxberry, банки (Сбер, Тинькофф, ВТБ, Альфа, Газпромбанк, Совкомбанк,
ПСБ), операторы связи (МТС, МегаФон, Билайн, Tele2, Ростелеком), Яндекс, Mail.ru, VK, OK,
маркетплейсы (Ozon, Wildberries, Авито, HH, ЦИАН, Фламп, Еда, Такси), СМИ и кино
(РБК, РИА, ТАСС, Ведомости, Кинопоиск, Лента, 2ГИС, Погода), Аэрофлот, РЖД, Московская биржа.
Список открыт для правки — лишнее можно удалить, нужное добавить. Чтобы вернуть поведение
«всё через VPN», достаточно переключить режим на «Все сайты через VPN».

Правила хранятся в `local:proxyRules` и применяются к PAC-скрипту:

```js
function FindProxyForURL(url, host) {
  host = (host || "").toLowerCase();
  if (host === API_HOST || dnsDomainIs(host, API_HOST)) return "DIRECT"; // API — напрямую
  for (var i = 0; i < RULES.length; i++) {
    var domain = RULES[i][0];
    if (host === domain || dnsDomainIs(host, domain)) {
      return RULES[i][1] ? PROXY_LIST : "DIRECT";
    }
  }
  return MODE === "listed" ? "DIRECT" : PROXY_LIST;
}
```

Фон пересобирает PAC-скрипт автоматически, как только список правил изменился
(подписка на `storage.onChanged`), поэтому переподключаться не нужно.

## API (без изменений)

Базовый URL: `https://naoborot-api.naoinfrastructure.com/api/v1/`.
Если хост недоступен, перебираются поды `0.…` — `9.…`, рабочий индекс запоминается.

| Метод | Путь                                                            | Назначение                         |
|-------|-----------------------------------------------------------------|------------------------------------|
| GET   | `auth/request_email_verification?reason=website_request&email=` | отправить код на почту             |
| POST  | `user_data` `{email, otp_code}`                                 | подтвердить код, получить подписку |
| GET   | `user_data?public_request_id=`                                  | обновить данные подписки           |
| POST  | `get_proxy` `{deviceId, deviceIp, publicRequestId}`             | получить прокси и логин/пароль     |

Внешний IP: `GET https://api.ipify.org?format=json`.
Идентификатор устройства: `crypto.randomUUID()` в `local:deviceId`.

Ответы разбираются вручную (без zod) в `src/shared/api.ts` и `src/popup/lib/api.ts`.

## Интерфейс

* **Главный экран** — кнопка подключения, блок аккаунта (почта, статус подписки, выход,
  оплата) и два режима проксирования прямо на верхнем уровне: «Только сайты из списка»
  (режим по умолчанию) и «Все сайты через VPN». Под ними сразу открыт редактор списка.
* **Кнопка «(i)»** в правом верхнем углу кнопки подключения открывает окно технической
  информации: адреса прокси-серверов, логин прокси, состояние соединения, режим
  и число правил, используемый хост API, внешний IP, ID устройства и версия расширения.
  Кнопка «Скопировать» кладёт всё это в буфер обмена.
* **Экран входа** — email → код из письма (4 цифры).

## Сборка и запуск

```bash
npm install
npm run build      # tsc --noEmit + popup + background -> dist/
```

Готовую папку `dist/` можно загрузить в браузер:
* Chrome/Edge — `chrome://extensions` → «Режим разработчика» → «Загрузить
  распакованное расширение» → папка `dist`;
* Firefox — `about:debugging` → «Загрузить временное дополнение» → `dist/manifest.json`.

Для установки без локальной сборки скачайте zip из актуального релиза
(страница «Releases» репозитория): `vpn-naoborot-chrome-*.zip` — для Chrome/Edge,
`vpn-naoborot-firefox-*.zip` — для Firefox, и повторите те же шаги с распакованной
папкой. CRX-файл напрямую установить нельзя — Chrome принимает CRX только из
Chrome Web Store (подробнее: «Сборка CRX» выше).

Для разработки: `npm run dev` (Vite), сборка фона отдельно — `npm run build:background`.

### Манифест: Chrome и Firefox

Ключ фонового контекста в MV3 у браузеров разный:

| | Chrome / Edge | Firefox |
|---|---|---|
| ключ | `background.service_worker` | `background.scripts` (event page) |
| как получить | `npm run build` (по умолчанию) | `npm run build:firefox` |

Chrome в MV3 отвергает `background.scripts` («requires manifest version of 2 or lower»),
а Firefox не поддерживает `background.service_worker`, поэтому в сборке два варианта
манифеста. Фон собран как classic-скрипт (IIFE) и одинаково запускается в обоих.

## Сборка CRX

```bash
npm run pack
```

Скрипт поднимает patch-версию в манифесте, собирает расширение и упаковывает его
в `dist.crx` средствами Chrome (`--pack-extension`) с ключом `crx-key.pem`.

> Версия поднимается автоматически, потому что Chrome **не обновляет** уже установленный
> CRX, если версия не выросла: без bump остался бы старый билд. Текущую версию
> видно в окне технической информации («Версия»).

* **ID расширения:** `ghpnhgmbnppjdneohnbnfgfpkfkmnpfo`
* Ключ `crx-key.pem` (RSA-2048) **нужно сохранить**: без него Chrome сгенерирует
  новый, и ID расширения изменится — обновление поверх старой версии перестанет
  работать. Файл добавлен в `.gitignore`, поэтому в CI он восстанавливается
  из секрета `CRX_PEM` (см. раздел «Релизы и CI»).

### Почему CRX «не устанавливается» (`CRX_REQUIRED_PROOF_MISSING`)

Начиная с Chrome 33, браузер разрешает установку CRX-файлов **только из Chrome
Web Store** — при попытке открыть сторонний CRX двойным кликом или перетащить
его в `chrome://extensions` появится ошибка `CRX_REQUIRED_PROOF_MISSING`.
Это политика Chrome, а не дефект файла. Поэтому основной способ установки —
распакованная папка (см. «Сборка и запуск» и zip-артефакты релиза).

CRX-файл при этом нужен для двух сценариев:

* публикация в Chrome Web Store — магазин принимает наш CRX, ключ (`crx-key.pem`)
  и ID расширения сохраняются;
* установка через корпоративную политику `ExtensionInstallForcelist` (управляемые
  Chrome-браузеры в организации).

Артефакт локальной сборки: `dist.crx`. Оформленный релиз собирает воркфлоу
Release (см. ниже).

## Релизы и CI

### CI (`.github/workflows/ci.yml`)

Работает на каждый push и pull request: тесты, обе сборки (Chrome- и
Firefox-манифест), распакованный `dist/` выкладывается артефактом
`extension-unpacked` — можно сразу загрузить в браузер для проверки.

### Release (`.github/workflows/release.yml`)

Запускается по push тега вида `v*`:

1. тесты;
2. ключ подписи `crx-key.pem` восстанавливается из секрета `CRX_PEM`;
3. версия в манифесте берётся из тега (`scripts/set-version.mjs`), без bump;
4. сборка и упаковка CRX штатным Chrome раннера;
5. zip распакованной сборки для Chrome (основной способ установки);
6. отдельная Firefox-сборка (`build:firefox`) и её zip;
7. GitHub Release с тремя артефактами (имена ASCII — GitHub API искажает
   юникод-имена файлов) и заметками: инструкция по установке + changelog
   из коммитов между тегами.

Артефакты релиза `vX.Y.Z`:

* `vpn-naoborot-X.Y.Z.crx` — подписанный CRX (для Web Store / политики);
* `vpn-naoborot-chrome-X.Y.Z.zip` — распакованная сборка для Chrome/Edge;
* `vpn-naoborot-firefox-X.Y.Z.zip` — сборка для Firefox.

Настройка секрета (Settings → Secrets and variables → Actions → New repository secret):

* имя: `CRX_PEM`;
* значение: base64 ключа — `base64 -i crx-key.pem | pbcopy` (macOS).

Первый релиз: тег должен совпадать с версией манифеста, например `v5.0.9`.

Новый релиз — просто тег:

```bash
git tag v5.0.10 && git push origin v5.0.10
```

## Тесты

```bash
npm test
```

* `test/rules.test.ts` — разбор доменов, сопоставление с хостом, поведение PAC-скрипта;
* `test/api.test.ts` — построение URL к API;
* `test/background.test.mjs` — фон целиком: `toggleProxy` → запрос `get_proxy` → PAC с правилами → состояние `connected`; **пересборка PAC после правки списка**; отключение;

  переключение режима проксирования, добавление домена, отправка `toggleProxy` в фон;

* `test/cdp.mjs` — стенд на настоящем Chrome через CDP (`Extensions.loadUnpacked`):
  загрузка расширения, проверки в popup и скриншоты.
